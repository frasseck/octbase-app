Act as a product manager and senior security expert doing a pre-demo review of Octbase — an existing Go (chi + PostgreSQL) modular monolith with a build-free vanilla-JS app frontend (`octbase-frontend/`), a phone-first static SPA (`octbase-mobile/`), and byte-identical shared JS (`octbase-shared/`). The context for this prompt: the product is being presented to an anxious enterprise client who fears quality defects and security incidents and expects a polished, competitive tool. This prompt records the review of `release_v15` and the fixes it drove, so the reasoning is not lost. It is **not** a request to re-do the work — it documents what was found and what shipped (commits `b73ae3a`, `876c0b9`).

The review fanned out four specialist passes — backend security, frontend security, test/quality health, and demo-readiness product QA — and synthesized them. Two headline conclusions: (1) the product is genuinely in good, demo-worthy shape — no exploitable XSS, no half-finished features, no placeholder text, backend suite green, coverage above the floor; (2) the real risk was **process and one SSRF bug**, not product polish.

## What was found

- **Demo-visible defects (all client-facing, all were sitting uncommitted).**
  - Duplicate task IDs: `seed.go` seeded two demo tasks with fixed `seq_number`s but never seeded `project_task_counters`, so the first UI-created task in the demo project came back as a duplicate `DP-1`. `NextSeqNumber` (`internal/workmanagement/planning_repo.go`) lazily starts the counter at 1 and collides.
  - Wrong top-bar titles on three routes: Settings showed "Projects", the dashboard kept the previously-visited title, and the Mindmap breadcrumb rendered the raw lowercase view id `mindmap` — all in `currentAppTitle()` / `renderDashboardPage` (`octbase-frontend/js/state.js`, `views-shell.js`).
  - Stale `index.html` asset hashes → the "Frontend checks" CI cache-busting guard was red.
- **Security — one genuinely exploitable issue (HIGH): SSRF via SCM `apiBaseUrl`.** A real-provider repository connection dialed its user-supplied `apiBaseUrl` through a plain `http.Client` with no egress controls (`internal/scmintegration/provider.go`, `handler.go`). Any authenticated project owner (auto-owner of a project they create) could point it at internal hosts or the cloud-metadata endpoint (`169.254.169.254`) and have the server issue the request, with provider error text reflected back. This also invalidated the `go-security` skill's SSRF invariant ("only outbound HTTP is OAuth token exchange to an operator-env `tokenURL`").
- **Security — demo-config must-dos (not code):** demo mode falls back to the public in-repo JWT key (`dev-secret-change-in-production`) unless `OCTBASE_JWT_SECRET` is set even in demo; the version tag reads "octbase beta" unless `OCTBASE_APP_VERSION` is stamped in the demo `.env`.
- **Clean (reassurance):** frontend cannot be XSS'd via task/comment/page content (esc discipline is CI-enforced, rich text goes through the DOMPurify policy, access token is memory-only + refresh token HttpOnly); backend is otherwise security-mature (parameterized SQL, AES-256-GCM with separate SCM/MFA keys, bcrypt cost-12 + policy, `alg=none` blocked, HMAC webhooks, uploads sniffed/allowlisted, BOLA guards on read and write, JWT fails closed in production).

## What shipped

1. **Demo defect fixes** (`b73ae3a`) — seed the counter with a `GREATEST`-idempotent upsert (new `internal/seed` regression test); resolve the correct localized title for Settings / dashboard / Mindmap; restamp `index.html`. Changelog `### Fixed` entry.
2. **SSRF hardening** (`876c0b9`) — two layers in `internal/scmintegration/ssrf.go`:
   - Preflight: `NewProvider` rejects a non-`http(s)` scheme or a literal internal-IP host with `400 SCM_URL_NOT_ALLOWED` (new stable code, surfaced via the standard `ProviderError → writeProviderError → shared.WriteError` shape).
   - Dial guard: all real SCM traffic uses a guarded `http.Client` whose `DialContext` resolves the host, refuses loopback/RFC1918/RFC6598/link-local (incl. metadata)/multicast, and dials the validated IP directly (DNS-rebind + redirect safe). TLS hostname verification is unaffected (ServerName is the URL host). The offline FAKE provider and public default hosts are exempt; a package-level `allowPrivateEgress` flag (default off, flipped only by the test binary's `TestMain`) lets integration tests reach loopback. Verified with `-race`, full backend suite green, coverage 74.4% (floor 73%), and a clean `go-backend-reviewer` pass.
